# 已R未退业务规则

## 1. 已R后生成内部退票账单，到期未来账再生成跟进记录

乘机人变为已R时，按照乘机人维度生成内部退票账单，从该乘机人的已R时间开始计算首次等待期。此时不生成已R未退跟进记录，也不进入“暂缓核实”。

- **首次到期仍未来账**：才自动创建一条已R未退跟进记录，初始状态为“待财务核实”，催款次数为0。首次生成时处理人可以为空；重复检查不得重复建单。
- **来账口径**：对应外部退票单已匹配或关联成功。仅导入、尚未匹配或关联，不算来账。期限内已来账的票直接走对账流程，不生成已R未退跟进记录。
- **建单后的核实**：财务核实票号是否真实已R，以及是否存在未导入、未匹配或需要补建的外部退票单。无法确认票号状态时转“待售后核实”；财务或售后确认真实已R且仍未来账，转“待催款”；确认实际未R，转“未R已关闭”。
- **建单后的催款与等待**：实际发出催款邮件后进入“已催款”，按本轮5个自然日计时；接受供应明确承诺时，按承诺退款时间计时。处理人接受继续等待时，转“暂缓核实”，必须手工指定下次核实时间。
- **跟进期间来账**：任一非终态下，对应外部退票单匹配或关联成功，自动转“来账已完结”。金额差异交差异单流程处理，不要求本模块先确认金额一致，也不以真实资金到账或整批结算完成为前提。

### 1.1 已R未退触发时长配置

该配置只决定**首次何时创建跟进记录**，不替代建单后各状态的下次核实时间、5日催款等待期限或承诺退款时间。

| 配置项 | 执行规则 |
| --- | --- |
| 通用默认天数 | 初始为15个自然日，业务人员可以修改。只有没有命中任何有效特殊规则时，才使用通用天数。 |
| 特殊规则条件 | 支持供应商、退票性质（自愿／非自愿）、出票航司。可以只限定一个维度，也可以组合限定多个维度；选定的条件须同时满足，未限定的维度视为不限。 |
| 特殊规则天数 | 命中一条，取该条天数；命中多条，取命中规则中的最长天数。条件更具体不代表优先级更高，通用天数不参与特殊规则的比较。 |
| 首次到期时间 | 从该乘机人的已R时间加上适用自然日天数。已R时间仅有日期时，以截止日结束为界，该日内仍处于等待期；有具体时刻时，达到对应时刻即到期。 |
| 配置变更的适用范围 | 所有已R且尚未建跟进单的票均按新配置重新判断。包括修改通用天数，以及新增、修改、停用、删除特殊规则。 |
| 缩短等待期 | 新期限已经到期且仍未来账的，在下次检查时建单，初始为待财务核实、催款次数0；重复检查不重复建单。 |
| 延长等待期 | 尚未建单的票按新的到期时间继续等待；包括旧期限已到但尚未被检查建单的票。 |
| 已建单的记录 | 继续按当前状态办理，不因首次触发配置修改而撤单、回退状态或重算当前状态期限。 |
| 检查顺序 | 先检查是否已建跟进单及外部单是否已关联；已建单不重复创建，已来账不新建。只有仍未建单、未来账且新期限已到期的票才创建跟进记录。 |

### 1.2 首次触发验收场景

| 场景 | 预期结果 |
| --- | --- |
| 通用15天，只命中一条7天特殊规则 | 采用7天，不与通用15天取最大值；到期仍未来账才建单。 |
| 供应商甲30天，供应商甲＋非自愿10天，同一张票同时命中 | 采用30天；即使10天规则限定条件更多，也不覆盖30天规则。 |
| 已R12天，适用规则由30天改为10天 | 保存后按10天重新判断，下次检查仍未来账则建一条待财务核实记录，次数0；重复检查不重复建单。 |
| 期限内已关联对应外部退票单 | 直接走对账流程；到期检查时不出现在已R未退跟进列表中。 |
| 未命中特殊规则，或尚未到达延长后的期限 | 分别采用通用天数，或按新期限继续等待，不提前建单。 |
| 已建单后修改首次触发配置 | 保持已有记录及当前状态期限；来账时仍按G01自动完结。 |

## 2. 本模块与资金核实的边界

本模块追踪的是退票账单是否存在并已对应到本笔记录，不负责判断资金是否真实退回，也不等待整批抵扣结算完成。

资金是否真实退回，由余额核对人员人工核实我方镜像余额与供应实际余额是否一致。本模块不以该余额核实结果作为自动完结条件。

- **供应已提供外部退票账单**：导入并匹配或关联成功后，本模块可以完结；即使所在批次尚未完成抵扣结算，也不继续在本模块等待。
- **供应未提供账单，但已实际退款**：不能直接完结。财务可手工建立外部退票单，关联到对应记录后，再按来账规则完结。
- **账单有金额差异**：来账后由差异单流程处理，不以金额不一致为由继续保留在已R未退流程中。
- **账单尚未匹配或关联成功**：不满足完结条件，继续按当前状态跟进。

## 状态设计

### 已确认规则与超时口径

1. **完结依据**：供应导入和财务手工建立的外部退票单均可作为依据；必须匹配或关联到本笔记录。金额是否一致、资金是否到账、整批是否结算，均不是本模块的完结校验条件。
2. **时间口径**：首次触发配置中的天数和实际催款后的5天均为自然日。时间仅精确到日期时，截止点为该日结束；填写了具体时刻时，按该时刻判断到期。首次触发采用第1.1节配置；5日催款等待和承诺退款时间分别按对应状态规则计时。
3. **首次触发与再次核实**：首次等待发生在建单前，已R时间加适用自然日天数得到首次到期时间；到期仍未来账才建单，初始待财务核实。暂缓核实仅用于建单后再次等待，下次核实时间必须由接受继续等待的处理人手工指定。
4. **催款计数**：催款次数默认0。每次实际发出催款邮件后进入已催款，系统自动加1，并记录本次进入时间；本轮5个自然日从该进入时间起算。
5. **催款超时**：超过本轮等待期限仍停留在已催款，自动转为供应反馈异常。不设置已催款到已催款的流转，也不通过等待期内追加催款重置计时。
6. **人工登记回复**：处理人收到供应回复后，应及时选择相应状态。系统不读取邮箱；供应已经回复但处理人未及时流转的，也可能进入供应反馈异常。
7. **迟到回复与商务结果**：已催款、供应反馈异常、承诺到期未退及商务升级中的回复，均按结果分流：接受继续等待则转暂缓核实，并指定下次核实时间；接受明确承诺则转已承诺退款，并记录承诺退款时间；无法接受则转商务升级中，原已在商务升级中的继续保留该状态。
8. **再次催款与升级**：供应反馈异常和承诺到期未退均可在实际再次发出邮件后转为已催款，也可由处理人决定转商务升级中。不按催款次数自动强制升级。
9. **商务未解决**：商务仍无结果或供应明确拒退，不关闭记录，继续保留商务升级中。本期不设放弃追款或损失核销终态。
10. **终态**：仅来账已完结、未R已关闭为终态；本版不设置终态回退或重开流转。未R已关闭仅能由待财务核实、待售后核实转入。
11. **批量流转**：列表勾选后直接流转仍用于同一当前状态，可统一填写日期后逐笔调整。Excel批量流转允许一份文件混合不同当前状态和不同目标状态，覆盖全部状态下既定规则允许的人工处理，不限于“已承诺退款”。逐笔校验合法流转及对应必填项；转“已承诺退款”时承诺退款日期必填。目标状态留空的行跳过；不通过的行列出原因并保持原记录，确认后仅更新通过的行。自动流转、来账优先和终态不可重开的规则保持有效。
12. **来账优先**：一旦对应外部退票单关联成功，停止本模块跟进，不再触发待核实或超时分支。执行下表T02—T23前，须确认记录仍在所列当前状态，且尚未关联对应外部退票单。

| **T09 已催款→供应反馈异常（自动）** | 无需填写。 | 超过本次进入已催款起算的5个自然日截止点，记录仍停留在已催款，且仍无对应外部退票单；按状态判断，不读取邮箱。<br><br>**举例**　11月2日10:00进入已催款。供应商6日已经回信，负责人还没登记。7日10:05系统检查时，本轮已超时，记录仍为已催款且未来账，系统标记为供应反馈异常。 |
| **T10 已催款→暂缓核实（人工）** | 在说明中填写供应反馈内容。<br>下次核实时间：必填。 | 供应反馈航司未退款或仍在处理中，处理人接受继续等待；下次核实截止时间晚于当前时间。<br><br>**举例**　11月3日供应商回复“航司还在审核，退款日期暂定不了”。负责人接受继续等，记录回复，把11月8日10:00定为自己再查这笔票的时间。 |
| **T11 已催款→已承诺退款（人工）** | 在说明中填写供应承诺内容，<br>承诺退款时间：必填。 | 供应给出明确、可接受的承诺退款时间，且承诺截止时间尚未到达；“下期”等表述须明确为可用于判断到期的日期或时刻。<br><br>**举例**　11月3日供应商回复“这张票我们11月10日退款”。负责人接受，把11月10日登记为供应商的承诺退款日，按这个日期跟进。 |
| **T12 已催款→商务升级中（人工）** | 在说明中填写升级原因。 | 供应承诺不可接受，或存在需要商务协调的事项，由处理人决定升级；不要求达到固定催款次数。<br><br>**举例**　供应商回信称“这笔应由另一家出票方处理”。负责人对退款责任归属有异议，在说明里写明争议，交商务协调。 |
| **T13 供应反馈异常→已催款（人工）** | 同 T08 一致 | 已实际再次发出催款邮件；进入后开启新一轮5个自然日等待。<br><br>**举例**　第一次催款已超时，记录已标为供应反馈异常。11月8日负责人再次发邮件追问这张票，催款次数从1变为2，从这次进入已催款重新等5个自然日。 |
| **T14 供应反馈异常→暂缓核实（人工）** | 同 T10 一致 | 收到迟到回复，供应反馈航司未退款或仍在处理中，处理人接受继续等待；下次核实截止时间晚于当前时间。<br><br>**举例**　催款超时后，11月8日供应商才回复“航司还在审核，暂时给不了退款日期”。负责人接受进展，登记反馈，约定11月12日10:00再查。 |
| **T15 供应反馈异常→已承诺退款（人工）** | 同 T11 一致 | 迟到回复提供明确、可接受的承诺退款时间，且承诺截止时间尚未到达。<br><br>**举例**　记录已因催款超时进入异常。11月8日收到迟来的回信“11月15日退款”，负责人接受，并把11月15日登记为供应商的承诺退款日。 |
| **T16 供应反馈异常→商务升级中（人工）** | 同 T12 一致 | 因持续无有效处理结果、承诺不可接受或其他需要协调的事项，由处理人决定升级；不按催款次数自动触发。<br><br>**举例**　记录已标为供应反馈异常。负责人电话核对票号后，供应商仍明确表示这张票不由他们处理。负责人记下争议，决定交商务核对责任。 |
| **T17 已承诺退款→承诺到期未退（自动）** | 无需填写。 | 承诺退款时间已过，仍无对应外部退票单；只填日期的，待该日结束后判断，有具体时刻的，按该时刻判断。此处“未退”仅指未来账。<br><br>**举例**　供应商承诺11月10日退款，记录中只填了日期。10日结束后仍未来账，11月11日早上系统检查时，将记录转为承诺到期未退。 |
| **T18 承诺到期未退→已催款（人工）** | 同 T08 一致 | 已实际再次发出催款邮件；进入后开启新一轮5个自然日等待。<br><br>**举例**　供应商原承诺11月10日退款，到期仍未来账。11月11日，负责人把这笔逾期票单独列出，再次发邮件追问。邮件发出后催款次数从1增至2。 |
| **T19 承诺到期未退→暂缓核实（人工）** | 同 T10 一致 | 原承诺到期仍未来账。供应商回复还在处理，未给出可接受的新退款日期。负责人同意继续等，并指定晚于当前时间的下次核实时间。<br><br>**举例**　供应商原承诺11月10日退款。到期仍未来账，11日对方回复“航司还在审核，新的退款日期暂时定不了”。负责人同意再等，记录回复，把11月15日10:00定为我方下次再查的时间。届时仍未来账，按 T02 转回待财务核实。 |
| **T20 承诺到期未退→已承诺退款（人工）** | 同 T11 一致 | 原承诺到期仍未来账。随后供应商给出新的、明确且尚未到期的退款时间，负责人接受这次承诺。<br><br>**举例**　供应商原承诺11月10日退款。到期仍未来账，11月11日收到供应商邮件“改为11月15日退款”。负责人接受，把11月15日登记为供应商新的承诺退款日。 |
| **T21 承诺到期未退→商务升级中（人工）** | 同 T12 一致 | 新的承诺不可接受，或仍无可接受的处理结果，由处理人决定交商务协调。<br><br>**举例**　供应商错过11月10日的承诺后，要求再延两个月。负责人认为这笔单无法接受这样的延期，写明原承诺和升级原因，交商务协调。 |
| **T22 商务升级中→暂缓核实（人工）** | 同 T10 一致 | 商务协调后确认仍需等待，且接受继续等待；下次核实截止时间晚于当前时间。<br><br>**举例**　11月12日，商务协调后确认航司正在复核，供应商仍给不出退款日期。处理人接受继续等，记下反馈，把11月18日10:00定为下次核实时间。 |
| **T23 商务升级中→已承诺退款（人工）** | 同 T11 一致 | 商务协调后取得明确、可接受的承诺退款时间，且承诺截止时间尚未到达；无可接受结果或供应拒退时，不执行该流转，继续保留商务升级中。<br><br>**举例**　11月12日商务与供应商协调，对方确认“11月18日退款”。处理人接受这个日期，登记为承诺退款日，按供应商的承诺跟进。 |
| **G01 任一非终态→来账已完结（自动）**<br>适用的9个当前状态：暂缓核实、待财务核实、待售后核实、待催款、已催款、供应反馈异常、已承诺退款、承诺到期未退、商务升级中。 | 无需为状态流转另行填写。<br>对应外部退票单：必须已存在并完成匹配或关联，系统记录关联结果；可来自供应导入，也可由财务手工建立。 | 对应外部退票单已匹配或关联成功。金额对平或存在差异均可完结，并交差异单流程处理；不校验实际资金到账或整批结算。仅知道钱已退回、但未建立或未关联外部单，不满足条件。<br><br>**举例**　一笔1000元的票还在商务跟进，财务将供应导入的980元外部退票单关联到该笔记录。系统随即完结跟进，20元差额交差异单流程处理。另一笔已核实退款的票，由财务手工补建并关联外部退票单后也会完结。 |

## Excel批量流转

### 导出与回填

- 保留记录编号、订单号、票号、乘机人、供应商、导出时状态及隐藏的导出校验标识，用于定位记录并核对导出后是否发生变化。
- 每笔可独立填写目标状态，支持混合导入；目标状态留空表示本次不处理。填写当前状态表示补充信息，不产生新的状态流转。
- 处理角色、处理人导出时带入现值，回填时按实际处理安排核对。“状态与必填规则”工作表列出每条人工流转的处理提示。旧版文件中的“业务确认”列可留空，导入时按其余字段校验。
- 说明选填。进入已催款时，催款次数默认原值加1；“催款次数修正值”选填，须为非负整数。保留当前状态编辑不加1、不重置本轮计时。

| 适用处理 | 必填与校验 |
| --- | --- |
| 所有人工更新 | 处理角色和对应处理人必填。处理人核对预览里各笔记录的目标状态、处理提示和校验结果。 |
| 从待财务核实流转 | 有效的追款负责人，带入该供应商对应负责人后核对。 |
| 目标为已承诺退款 | 承诺退款日期必填；进入时须明确且尚未到期。“下期会退”须先落实到具体日期。 |
| 目标为暂缓核实 | 下次核实时间必填；进入时截止时间须晚于当前时间。 |
| 目标为已催款 | 本轮催款邮件实际发出后可转入。最近催款时间必填，最晚为当前时间。 |
| 目标为未R已关闭 | 财务或售后核实票号实际未R后，可从待财务核实、待售后核实转入。 |
| 自动流转与终态 | Excel不能强行替代到期检查或外部单关联。来账已完结须有对应外部退票单关联依据；两种终态均不能回退或重开。 |

### 校验预览与确认

1. 读取.xlsx或.xls的“批量流转”工作表，逐行检查记录、目标状态、必填日期、人员及重复编号。原型每次最多1000笔、10MB。日期支持Excel日期值或明确的年月日、日期加时刻，按北京时间解释。
2. 预览显示每行当前状态、目标状态、本次日期、处理人和校验结果。通过的行显示该目标的处理提示。不通过或跳过的行显示具体原因。
3. 点击“确认更新”一次提交通过的行。可下载带有逐行原因的校验结果，修改后重新导入。
4. 提交前再次核对最新记录和来账情况；预览后发生变化时先重新校验，要求核对后再确认。每笔更新写入操作记录，说明分别保留。已更新行的旧文件重复导入会被阻止，避免重复催款计次。
5. 列表、详情与导入结果使用同一份本地演示数据。正式系统仍需实现真实账号权限、后台接口及事务并发控制。
